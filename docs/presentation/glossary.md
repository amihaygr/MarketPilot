# MarketPilot - מילון ומודלים מחשבתיים

| מונח | הסבר פשוט | איך לזכור |
|---|---|---|
| Event | עובדה שקרתה בזמן מסוים | מעטפה עם זהות, זמן ותוכן |
| Schema | המבנה והטיפוסים של הנתון | חוזה בין מי ששולח למי שקורא |
| Producer | שירות שמפרסם events | שולח מכתבים לסניף הדואר |
| Consumer | שירות שקורא events | נמען עצמאי עם סימנייה משלו |
| Topic | ערוץ events ב-Kafka | תיקייה לוגית של הודעות מאותו סוג |
| Partition | חלוקה סדורה בתוך Topic | מסילה שבה נשמר סדר מקומי |
| Offset | מספר המיקום ב-Partition | מספר סידורי של הודעה על המסילה |
| Consumer group | צרכנים שחולקים עבודה | צוות שמתחלק במחיצות |
| Streaming | עיבוד מתמשך של events נכנסים | פס ייצור שעובד כל הזמן |
| Micro-batch | קבוצת events קטנה בעיבוד Streaming | סל קטן שמתרוקן כל כמה שניות |
| Batch | Job עם קלט תחום וסוף ברור | סגירת יום וחישוב מחדש |
| Checkpoint | מצב ההתקדמות של Streaming | סימנייה עמידה לאחר restart |
| Watermark | גבול התקדמות או פרסום | חותמת עד היכן הנתונים תקפים |
| Idempotency | retry בלי תוצאה כפולה | לחיצה כפולה שמייצרת הזמנה אחת |
| Business key | זהות עסקית של רשומה | מה הופך bar אחד לייחודי |
| Upsert | Insert או Update לפי key | צור אם חסר, עדכן אם קיים |
| Bronze | חומר גלם immutable | המקור שלא מתקנים בדיעבד |
| Silver | נתון נקי וקנוני | חומר גלם שעבר ניקוי ואחידות |
| Gold | נתון מוכן ליישום | מוצר מדף לשאילתות ול-Dashboard |
| Parquet | פורמט עמודתי דחוס | קובץ יעיל לסריקות Analytics |
| Provisional | נתון חי שטרם אושר סופית | מה ידוע עכשיו |
| Certified | נתון של יום סגור שעבר DQ | מה מאושר לאחר הבדיקה |
| Data Quality | כללים שחוסמים פרסום שגוי | שער לפני Gold Certified |
| Lineage | שרשרת המקור והעיבוד | תעודת המסע של הרשומה |
| Replay | עיבוד חוזר של history | להריץ שוב מהמקור הגולמי |
| Backfill | מילוי או תיקון טווח היסטורי | Replay ממוקד לפי תאריכים וסמלים |
| Orchestration | ניהול סדר ותלויות של jobs | מנהל העבודה, לא העובד עצמו |
| Healthcheck | בדיקה ששירות מסוגל לפעול | דופק טכני של container |
| Freshness | כמה עדכני הנתון | הזמן מאז האירוע האחרון |
| DLQ | מקום ל-events שנכשלו | תיבת חריגים עם סיבה |
| Manifest | רשימת תוכן וראיות לארכיון | תעודת משלוח עם counts ו-hashes |
| SHA-256 | טביעת אצבע קריפטוגרפית | שינוי קטן בקובץ משנה את החתימה |
| API boundary | השער היחיד של ה-UI לנתונים | הדפדפן מדבר עם פקיד, לא עם הכספת |
| ADR | מסמך החלטה ארכיטקטונית | למה בחרנו כך ומה המחיר |

## הבדלים שקל להתבלבל בהם

- **Kafka מול MinIO:** Kafka מעביר ושומר log לפי offset; MinIO שומר objects לטווח ארוך.
- **Spark מול Airflow:** Spark מבצע חישוב; Airflow מחליט מתי ובאיזה סדר להריץ Batch.
- **MinIO מול MariaDB:** MinIO ל-raw/Parquet/archive; MariaDB ל-Gold serving.
- **Health מול Freshness:** שירות יכול להיות healthy אבל להציג נתונים ישנים.
- **Backup מול Archive:** backup משחזר מערכת; archive משמר dataset סגור ומאומת.
- **Retry מול Duplicate:** retry הוא פעולה חוזרת; idempotency מונע תוצאה עסקית כפולה.
- **Event time מול ingestion time:** הראשון הוא זמן האירוע במקור; השני זמן הקליטה במערכת.
- **Live מול Certified:** הראשון ממקסם מהירות; השני ממקסם אמון במחיצה סגורה.
